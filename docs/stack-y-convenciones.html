1. Tecnologías y Runtime por Servicio

Distribución técnica acordada por los 4 integrantes para cubrir los requisitos del docente.

Componente / Microservicio Stack Tecnológico Responsabilidad Principal en la Solución
Frontend Angular 22 (TypeScript) SPA única: portal público, panel del organizador y panel administrativo.
API Gateway Spring Cloud Gateway (Spring Boot 4.1 · Java 21) Punto de entrada único: validación JWT, CORS global, límite de peticiones en memoria y ruteo perimetral.
campaign-service Spring Boot 4.1 (Java 21) Núcleo del negocio (Core Domain): estados, moderación, metas y reglas de campañas.
contribution-service Spring Boot 4.1 (Java 21) Núcleo del negocio (Core Domain): aportes, compromisos de pago y recaudación exacta.
identity-service NestJS 12 (Node.js 24 LTS) Gestión de cuentas, asignación de roles y emisión de tokens JWT seguros.
notification-service NestJS 12 (Node.js 24 LTS) Envío asíncrono de correos (Mailpit) y despacho a la bandeja interna de avisos.
update-service Django 5.2 LTS + DRF (Python 3.13) Publicación de novedades, avances y bitácora del creador de la campaña.
search-service Django 5.2 LTS + DRF (Python 3.13) Catálogo de solo lectura (CQRS) con filtros facetados y búsqueda de texto completo.

2. Bases de Datos y Almacenamiento (Database per Service)

Ningún microservicio puede compartir o consultar directamente el almacén de datos de otro componente.

Servicio Propietario Motor de Base de Datos Tipo de Almacén Justificación Arquitectónica
identity-service PostgreSQL 18 Relacional (ACID) Garantía estricta de unicidad en emails, autenticación y auditoría de usuarios.
campaign-service PostgreSQL 18 Relacional (ACID) Integridad en transiciones de estado de campañas y reglas de moderación.
contribution-service PostgreSQL 18 Relacional (ACID) Precisión monetaria exacta sin redondeos con NUMERIC(12,2).
update-service PostgreSQL 18 Relacional (ACID) Publicaciones cronológicas y relación con los autores de cada campaña.
search-service PostgreSQL 18 (FTS) Búsqueda Textual Lado de consultas CQRS indexado con tsvector y pg_trgm.
notification-service PostgreSQL 18 Relacional (ACID) + JSONB Bandeja de avisos, contactos y aportantes por campaña; el contenido variable de cada aviso va en una columna JSONB.
Un solo motor para los seis servicios. El enunciado pide una base por servicio, no motores distintos. Todos los datos son estructurados, así que PostgreSQL cubre todo y el equipo aprende, migra y respalda un solo motor. Detalle en el ADR 0002.

Necesidades que no son bases de datos

Necesidad Solución Por qué
Imágenes de campañas Archivos en el volumen de Docker campaign-images; en campaign-db solo la ruta, el tipo y el tamaño Guardarlas dentro de la base la agranda y vuelve lentos los respaldos.
Límite de peticiones del gateway En la memoria del gateway (Bucket4j + Caffeine) Con un solo gateway no hace falta compartir contadores entre instancias.
